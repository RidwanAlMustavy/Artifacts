# Shipping Imperfect Software

Pixel perfection is the enemy of market feedback. Many early-stage startups get trapped in an endless refinement cycle, trying to polish an execution before knowing if anyone actually wants the feature.

Here is why you need to embrace shipping things that make you feel slightly uncomfortable.

## Real Data Always Beats Assumptions
You can hold internal feedback sessions, run prototypes through user testing cohorts, and debate corner cases for weeks. But nothing matches the truth of a real user using their own real data in their normal environment. The sooner you get to that stage, the sooner you start building what they actually need.

## Defining 'Acceptable' Friction
Shipping fast doesn't mean shipping bugs that corrupt databases. It means leaving out secondary features, using basic un-styled table components instead of rich grids, and leaning heavily on manual back-end workflows to simulate automation.

Build the core value engine flawlessly. Leave the wrapping paper for version two.
